# H3C Magic NX15000：怎么进去、配置在哪、能改什么

> 型号 / 固件 / 地址 / 凭据键名见 [`../../AGENTS.md`](../../AGENTS.md)「网络设备」 · IPv6 入站的具体案例见 [ipv6-inbound.md](ipv6-inbound.md)

## 一句话

Web UI 能改的很少（**IPv6 防火墙的开关被固件跳过**）；真要动防火墙只能 `debug.asp → telnet 15000 → debugshell` 进 root —— 但**改动一律不持久**。

## 进 root

| 步骤 | 操作 |
| --- | --- |
| 1. 开 telnet | `http://192.168.124.1/debug.asp` → 勾「启用 Telnet 管理」→ 应用 |
| 2. 连 | `telnet 192.168.124.1 15000` |
| 3. 提权 | 输入 `debugshell` → `root@OpenWrt:/#`（OpenWrt Chaos Calmer / armv7l） |

- ⚠️ **实测这版固件连上不验密码**，直接是 `<H3C_NX15000>` 提示符，输 `debugshell` 即 root。
- 关闭：同页取消勾选再应用。该操作只提交 `CMD=Asp_SetTelnetDebug`，不影响其他设置。
- 同页还有 `HWNAT`（硬件 NAT）开关。

## Web UI 结构（要抓接口时有用）

```
/home.asp  frameset
  ├── title.htm
  ├── menu_admin.asp    菜单（onclick 里带目标 .asp）
  └── main_screen       内容页

提交：POST /goform/aspForm     字段 CMD / GO / param
查询：GET  /AJAX/ajaxget?ajaxmsg=aspGetGroup(...)
```

- 手机 UA 会跳 `/mobile.asp`（简化版，功能少一半）；用桌面 UA 或直接访问 `/home.asp`。
- 部分页直接访问返回 **400**（需要会话/来源），从菜单点进去才正常。

## 防火墙结构（要加规则必须知道挂在哪）

```
FORWARD (policy DROP)
└─ delegate_forward
   ├─ forwarding_rule
   ├─ ACCEPT  ctstate RELATED,ESTABLISHED
   ├─ zone_lan_forward   (in br-lan)
   │   ├─ forwarding_lan_rule
   │   ├─ zone_wan_dest_ACCEPT
   │   └─ zone_lan_dest_ACCEPT
   └─ zone_wan_forward   (in eth0)
       ├─ MINIUPNPD                      ← UPnP 打洞
       ├─ forwarding_wan_rule            ← ★ 自定义 ACCEPT 加这里
       ├─ ACCEPT icmpv6 type 1/2/3/4     ← 差错报文
       └─ zone_wan_dest_REJECT           ← 兜底拒绝（就是 IPv6 入站不通的元凶）
```

**关键点**：规则是**从上往下第一条匹配即生效**，所以自定义 ACCEPT 必须落在 `forwarding_wan_rule`（第 2 条），不能放到末尾的 REJECT 之后。

`iptables`（IPv4）是同样的链结构，但 IPv4 入站还要过 NAT（`app_vServers.asp` 的虚拟服务器 / DMZ）。

## 能力边界

| 功能 | 有吗 |
| --- | --- |
| IPv6 防火墙 UI | ❌ `IsSupport_FireWall = 0`，页面被固件跳过 |
| IPv6 端口映射 | ❌ 无此概念（IPv6 不经 NAT，只需放行） |
| IPv4 端口映射 / DMZ | ✅ 高级设置 → 地址转换（当前 **0 条规则**、DMZ 未启用） |
| UPnP | ✅ `app_upnp.asp`；IPv6 转发链第 1 条就是 `MINIUPNPD`，开启后可自行打洞 |
| VLAN / 2.5G 口 / IPTV | ✅ |
| DDNS | ❌ 无此页面 |

## 为什么改了不保存

```
mount | grep ' / '
overlayfs:/tmp/root on / type overlay (rw, ..., upperdir=/tmp/root/upper)
                                          └─ 在 tmpfs（内存）里
```

- `/etc` 下的一切改动**重启即失**（`rc.local`、crontab 同样无效）
- 闪存 `/mnt`（ubifs）上只有厂商配置：**`/mnt/cfg/startup`**（`key=value` 格式，**不是 shell 脚本**），由厂商二进制解析
- `/mnt/cfg/startup` 里有 `@vserver`（IPv4 端口映射，所以 v4 配置能持久），**没有任何 `firewall` / `ip6` / `acl` 段** → 结构上没地方放 IPv6 放行规则

→ 结论：**没有可用的持久化钩子**。取舍与替代方案见 [../decisions/0001-ipv6-inbound.md](../decisions/0001-ipv6-inbound.md)。

## 常用命令速查

```bash
# 看/改 IPv6 转发放行
ip6tables -nL forwarding_wan_rule --line
ip6tables -A forwarding_wan_rule -d ::71e/::ffff:ffff:ffff:ffff -j ACCEPT
ip6tables -D forwarding_wan_rule <与上面完全一致的规则>

# 网络状态
ip -6 route show          # PD 路由、默认路由
ip -6 neigh               # 邻居（≈ arp）
ip -6 addr show br-lan    # LAN 侧地址
ip -6 route get <dst>     # 这个目标走哪

# 抓包（busybox 自带 tcpdump）
tcpdump -i any -nn "ip6 and tcp" -c 20
```
